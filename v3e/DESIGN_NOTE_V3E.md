## 1. Why (CRITIC2_v6 section 3, remaining rejection reasons 2, 3, 5)
(R2) Headline bnq comparison: no CP-SAT tuning signal, one CP-SAT model, no native local search, unexplained ~1 s ls_nb start-up on bnq (first call in a fresh child after an 8x8 warm-up took 0.60 s). (R3) probSAT vs WalkSAT could not be separated because the 3-SAT cells sit at the SAT ceiling for SLS, and ls_nb was never run on 5-SAT. (R5) "Latin loss was an implementation effect" rests on a bundle (speed, noise 0.1 vs 0, tie-break) without ablation. v3e answers these with the experiments E1 to E6 below. NOT addressed: a second CP-SAT model of bnq (diagonal AllDifferent on column variables), CP-SAT with a min-conflicts hint, Kissat/march/kcnfs (R2b, R2c, R3 complete-solver part), and the pre-registration-strength and novelty objections (R1, R4, R6).

## 2. Solvers and instruments
- `ls_c` (E2): `nq_ls_c.c`, same algorithm as `lsnb_bnq` (nq_v3.py): greedy row-by-row start with min of (column + two diagonal conflicts + 5 * blocked) and random ties; then random conflicted queen (conflict = col + d1 + d2 - 3 + blocked > 0) moved to a min-conflict column of its row, ties random; noise 0; restart after 20000 moves; clock checked every 500 moves. Differences stated: xorshift64* generator instead of Mersenne Twister (single runs differ from ls_nb, distribution should not); the numba kernel's noise draw is mirrored by a discarded draw. Compiled `gcc -O3 -march=native`. Called as a subprocess `nq_ls_c BOARDFILE SEED BUDGET`; the child writes the board (n lines of '0'/'1') to a temp file, runs the binary, parses `SAT secs q0 ... q(n-1)` or `TO secs`. The timed region (t) starts at the beginning of solve(), so it includes file write, process start, run and parse, exactly as other solvers include model building. The internal budget is the remaining time minus 0.02 s. Every answer goes through the existing verifier. If gcc is missing the notebook stops at the smoke cell with a clear message and E2 is NOT EVALUABLE.
- `ls_nb_n10` (E3): ls_nb on qwh/qcp with noise 0.1 (the ls_py setting); `ls_nb` keeps noise 0 (nq_v3 NB_NOISE). Stage `long3e`: `ls_py` (pure Python, noise 0.1) with T = 100 s, seeds 300-304.
- `ls_nbk` (E4): WalkSAT/SKC for any clause length (ragged clauses, numba), noise 0.567 as ls_nb on 3-SAT (not tuned for k = 5; stated limit). Needed because ls_nb is hard-wired to k = 3. On 3-SAT the original `ls_nb` is used. `probsat_nb`, `cadical195`, `cpsat_strong` unchanged from v3d.
- `cpsat_tuned` (E5): cpsat_strong model plus the parameter text chosen by `tune_v3e.py` for bnq; run ONLY on bnq n=200 and ONLY if a non-default variant won; otherwise not run (it would equal cpsat_strong) and E5 reports NO SIGNAL.
- Warm-up fix (E1): `warm_up()` calls the real `solve()` path once per kernel on a real-size instance of every family before any fork: bnq n=200 p=.9 (ls_nb, ls_c), qwh N=40 h=.4 and qcp N=40 f=.42 (ls_nb, ls_nb_n10), 3-SAT n=2000 r=4.2 (ls_nb, probsat_nb), 5-SAT n=200 r=20.5 (ls_nbk, probsat_nb), 0.3 s each. Residual overhead is measured: every kernel's first-call duration in each child is recorded (nb_seed, init and steps kernels) and written to `OUT.first.csv` (family, size, param, seed, solver, first_s = sum of first-call durations, detail). For `ls_c`, first_s = wall time of the subprocess minus its internal time (spawn + start-up). The first call includes the first chunk of real work (about 1 ms to 10 ms), which is part of the measured residual. The cause of the old 0.6 s is NOT known; E1 only tests whether it is gone.

## 4. Tuning (E5; run BEFORE the stage; `tune_v3e.py`, seeds 2000-2002 only)
`tune_cpsat.tune_cp` (v3d, unchanged) with the 8 variants of `nq_v3d.CP_VARIANTS` (default, linearization_level 0 / 2, PORTFOLIO_SEARCH, FIXED_SEARCH, symmetry_level 0 / 2, cp_model_presolve false), cells bnq n=100 p=.90 and p=.94, 3 seeds, T = 5 s, strong model, 1 worker: 48 runs, 6 per variant. Rule as v3d: winner = most solved, tie lower PAR2 (2T per failure), tie default; a non-default winner must beat default by >= 1 solved run or >= 10% PAR2, else default stays. Output `tuned_cpsat_bnq.json` (empty `params` = no signal). Tuning cells are inside the stage grid at n=100 but the tuning seeds are not stage seeds. Limit: n=100 p=.94 may give 0 solved for every variant; n=100 p=.90 is the only informative cell.

## 5. Hypotheses (E2 PRIMARY; all others exploratory; directions fixed before data)
Definitions: solved = verified SAT within T. Single proportions: Wilson 95%. Paired differences: percentile bootstrap, 10,000 resamples, numpy seed 0. Exact McNemar (one-sided where a direction is stated; two-sided = 2 x one-sided of the larger discordant count, capped at 1). Cells with < 16 completed paired instances are "not evaluable". k-of-m verdicts: SUPPORTED if >= k cells pass; NOT EVALUABLE if k can no longer be excluded; else FALSIFIED. Holm over the exploratory hypotheses that have a McNemar p (E4, E5b); E1, E3, E5, E6 are descriptive without p. Thresholds are effect-size choices made here, not derived.
- **E2 (PRIMARY, native baseline).** bnq n=200, p in {.84, .88, .90, .92}: a cell passes if |solved(ls_c) - solved(ls_nb)| <= 0.10 AND solved(ls_c) - solved(cpsat_strong) >= 0.5 (point estimates; paired CIs reported). Supported if >= 3 of 4 cells pass. Reading: compiled local search in C solves the same fraction as ls_nb and still beats CP-SAT, so the bnq advantage is not a numba artefact. Falsified if C is more than 0.10 away from ls_nb (either direction) or loses the 0.5 margin in two cells.
- **E1 (start-up cost).** Supported if (a) median first-kernel-call sum over all ls_nb bnq children <= 0.10 s AND (b) min solved time of ls_nb on bnq n=200 over the 7 p cells <= 0.30 s (v3d: about 1.0 s). Falsified otherwise (then the residual is reported as measured).
- **E3 (bundle ablation).** Over the 16 Latin cells (qwh h .30-.45, qcp f .38-.50, N 30 and 40): |solved(ls_nb) - solved(ls_nb_n10)| <= 0.15 (3 of 20 instances; 0.10 would be too tight for n = 20 sampling noise) in >= 12 of 16 cells = noise is not the driver of the Latin reversal (speed is). Falsified otherwise (noise matters). Descriptive only: ls_py at T = 100 s on seeds 300-304 vs ls_nb_n10 and ls_nb (T = 10 s) on the same 5 instances. ls_py is 30 to 90 times slower than ls_nb (v6 ratios), so 10 x budget does not equalise speed; this arm is a partial check, not an equivalence test.
- **E4 (WalkSAT vs probSAT off the ceiling).** probsat_nb solved - WalkSAT/SKC solved (ls_nb on 3-SAT, ls_nbk on 5-SAT) >= +0.10 in >= 3 of 9 cells (ksat5 n=200 r 20, 20.5, 21; ksat n=1000 and 2000, r 4.0, 4.1, 4.2). SUPPORTED = "WalkSAT = probSAT" is not supported at these sizes. FALSIFIED = no separation (then the claim survives a test where it could have failed). p = 3rd smallest one-sided McNemar. Reported: cadical195 fraction, share solved by any of the three, number of cells where both SLS are >= 0.95 (still ceiling).
- **E5 (CP-SAT tuning signal on bnq).** SIGNAL if tuning picked a non-default variant under the section 4 rule, else NO SIGNAL. E5b (only with signal): solved(cpsat_tuned) - solved(cpsat_strong) >= +0.10 on bnq n=200 in >= 2 of the 4 E2 cells; p = 2nd smallest one-sided McNemar. Information: ls_c vs cpsat_tuned difference in the E2 detail lines.
- **E6 (cost of the C arm).** Supported if median (wall - internal) of ls_c over all children <= 0.05 s AND median paired ratio t(ls_c)/t(ls_nb) <= 1.5 over bnq n=200 instances both solve. Purpose: E2 is not driven by spawn cost or by a slower/faster kernel.
All verdicts are reported, none dropped. Primary hypothesis labels are not changed after data.

## 6. Analysis (`analyze_v3e.py MAIN.csv --long LONG.csv --tuned tuned_cpsat_bnq.json`)
Reuses analyze_v3d.py functions (Wilson, McNemar, Holm, bootstrap, strict-budget check: stops if a late answer remains or an instance gets both SAT and UNSAT). Reads MAIN.csv.first.csv. ## 7. Known limits stated in advance
Single CP-SAT model of bnq (R2b/R2c open); C uses another RNG and `-march=native`; ls_nbk noise not tuned for k = 5; unsolved 3-SAT instances at n = 1000/2000 are not proven UNSAT (cadical195 may not decide them in 10 s); ls_py 10 x budget is not speed-matched; start-up cause unexplained, only measured; 20 instances per cell; one Kaggle CPU model per session (recorded); first-call time includes the first chunk of real work; cell sets and thresholds are my choices; tuning for E5 has 6 runs per variant (low power); E1 threshold values are chosen from one earlier observation (0.6 s, about 1.0 s).
