## 2. Solvers and instruments (all wrap v3e/v3d/v3 without editing them)
- `ls_nb_fixed` (F1): `lsnb_bnq` of nq_v3.py line for line, with the kernel set chosen by `diag_f1.py` through a FIXED rule (section 4). Candidate fixes, in order of preference: `same_call` (parent warm-up calls `bnq_init`/`bnq_steps` directly with the exact argument types of the real call at n = 50, 100, 200: int64 C-contiguous arrays, float noise, int steps; kernels unchanged), `sig` (kernels re-declared with explicit eager signatures, compiled in the parent before any fork), `cache` (kernels re-declared with `cache=True`, `NUMBA_CACHE_DIR` set before numba loads). If the rule finds no fix, `f1_fix.json` has `fix: null`, `ls_nb_fixed` is not run and F1 is FALSIFIED. A fix must reduce the cost, not move it: nothing is excluded from the timed region (the timer starts at the start of `solve()` as for every solver).
- `ls_py_n0` (F3): `lspy_latin` of nq_v3.py called with `noise=0.0`; rng, restarts, tie-break and everything else as `ls_py` (`lspy_latin` already has a `noise` argument, so no algorithm is re-implemented). `ls_py` = noise 0.1 (unchanged), `ls_nb` (noise 0), `ls_nb_n10` (noise 0.1) from v3e.
- `ls_nbk_n30/n40/n50/n65` (F2): `walksat_k` of nq_v3e.py with noise 0.30/0.40/0.50/0.65; plain `ls_nbk` is the 0.567 point of the sweep (v3e setting). `probsat_nb` and `cadical195` unchanged references.
- `cpsat_alt` (F4): second CP-SAT model of blocked n-Queens. One integer per row with the FULL domain 0..n-1 (not the free columns), `AddElement(q_r, [blocked_r[c] as constants], 0)` forbids blocked cells, `AddAllDifferent(q)`, `AddAllDifferent(q_r + r)`, `AddAllDifferent(q_r - r)`. It differs from `cpsat_strong` (domain holes, same three AllDifferents) in how blocked cells enter the model; it is a second formulation, not a second solver. Default parameters, 1 worker; `cpsat_alt_w4` = 4 workers (as `cpsat_strong_w4`). No hint, no tuning (fairness). The model is tested locally with a fake CP-SAT of real semantics against brute force (4 boards).
- `ls_py` on bnq (F5): `lspy_bnq` of nq_v3.py, interpreted, unchanged.
- Warm-up: v3f `warm_up()` compiles the kernels of the families in the stage on real-size instances through the real `solve()` path (0.3 s each) before any fork. The first-call time of every kernel in each child is logged to `OUT.first.csv` (as v3e) also for `ls_nb_fixed`.

## 4. F1 diagnosis and the fix rule (`diag_f1.py`, about 10 CPU minutes, serial)
Each condition is a fresh parent process (numba cache env and kernel variant are set before numba loads). The parent warms up, measures one control pass, then runs 5 forked children (the harness way) and, for three conditions, 3 spawned fresh interpreters. Each process times around each call `nb_seed`, `bnq_init`, `bnq_steps` (first call) and again `init`/`steps` (second call), n = 200, p = .9, noise 0.0, steps 500; it counts numba compile events (`numba.core.event`, -1 if unavailable) and dispatcher signatures before/after. One row per process in `f1_diag.csv`; the argument types of the real call on the n=8 warm-up board and the n=200 board are compared in `f1_types.json`.
Conditions: `base_none` (lazy kernels, no warm-up; fork 5, spawn 3), `warm_tiny` (n=8 warm-up as nq_v3), `warm_real` (n=200 warm-up through the real loop: the v3e status quo), `warm_same` (direct calls with the exact types of the real call; = candidate `same_call`), `sig` (explicit eager signatures; fork 5, spawn 3), `cache_cold` (cache=True, empty `NUMBA_CACHE_DIR`) and `cache_warm` (same dir, second parent; fork 5, spawn 3) (= candidate `cache`; the harness picks `NUMBA_CACHE_DIR` itself).
Rule (code: `choose_fix`): first-call sum = t(nb_seed) + t(bnq_init) + t(bnq_steps) of a forked child. The fix is the FIRST candidate in the order `same_call`, `sig`, `cache` whose forked-child median first-call sum is <= 0.10 s in every one of its conditions with >= 5 children (`cache` needs both `cache_cold` and `cache_warm`). None qualifies: `fix = null`. `baseline_reproduced` = `warm_real` median > 0.10 s is reported and does not change the rule: if the 1.1 s is not reproduced, `same_call` qualifies trivially, and F1 then tests whether `ls_nb` was fine all along (its min solved time).
Reading of the diag rows (descriptive): compile events or signature growth in a forked child after a real-size warm-up = dispatch specialisation or recompile in the child; zero events with a slow first call = something else (page faults, lazy linking, fork effects); spawn rows with and without cache show what a per-run fresh process would cost. The cause is reported as measured; it is not asserted beyond the rows.

## 5. Hypotheses (F1 PRIMARY; all others exploratory; directions and numbers fixed before data)
Definitions: solved = verified SAT within T. Single proportions: Wilson 95%. Paired differences: exact McNemar (two-sided = 2 x one-sided of the larger discordant count, capped at 1) reported per comparison, unadjusted, descriptive only. Cells with < 16 completed paired instances are "not evaluable" (F3: < 60 of 80 pooled pairs). For every "k of n cells" or pooled rule the verdict is deterministic and NO p-value is reported (CRITIC3_v8 note: the order-statistic p is invalid; no Holm either). Thresholds are effect-size choices made here, not derived.
- **F1 (PRIMARY, a fix exists).** SUPPORTED iff `f1_fix.json` has a fix AND the minimum solved time of `ls_nb_fixed` over bnq n=200, p in {.84, .88, .90, .92} (80 runs) is <= 0.30 s AND, in each of these 4 cells, |solved(ls_nb_fixed) - solved(ls_nb)| <= 0.05. NOT EVALUABLE if a cell has < 16 paired instances; FALSIFIED otherwise (including `fix = null`). Reading: the 1.1 s is an artefact of the harness that a documented change removes without changing what is solved (v3e: ls_c compute is 0.008-0.21 s; threshold 0.30 s).
- **F1b (exploratory).** Median first-kernel-call sum of `ls_nb_fixed` bnq children <= 0.10 s (side file); `ls_nb` reported alongside.
- **F2a (WalkSAT sane).** `ls_nbk` (noise 0.567) solves >= 0.95 in ALL 4 cells ksat5 n=200 r = 12, 14, 16, 18. SUPPORTED = no sign of a bug at k = 5 far below threshold; FALSIFIED = ls_nbk is unreliable and every 5-SAT WalkSAT statement must be dropped. probSAT and CaDiCaL fractions reported.
- **F2b (noise artefact).** At r = 20 and 20.5 the best of the 5 noise settings {.30, .40, .50, .567, .65} solves >= 0.50 in >= 1 of the 2 cells. SUPPORTED = the v3e "WalkSAT 0/60" reflects the untuned noise value, not an unfixable defect; FALSIFIED = WalkSAT stays far from probSAT (20/20 in v3e) for every noise value. Best-of-5 is selection-inflated; the full noise table with Wilson intervals is reported. Only meaningful if F2a is SUPPORTED.
- **F3a (slow noise 0 reaches fast noise 0).** Over the 16 Latin cells x seeds 400-404 (80 paired instances): solved(ls_py_n0, 100 s) >= solved(ls_nb, 10 s) - 0.10 x n (n = paired instances). SUPPORTED = noise 0 is enough for the slow search to reach the fast one even without compiled speed (supports "noise" as driver); FALSIFIED = compiled speed (or the budget-unmatched comparison) matters. Caveat stated in advance: 100 s vs 10 s is not speed-matched (ls_py is 30-90 x slower).
- **F3b (noise inside the slow search).** solved(ls_py_n0) - solved(ls_py, noise 0.1; both 100 s) >= 0.15 x n. SUPPORTED = noise matters in the interpreted implementation too. NOT EVALUABLE if arm 2 was not run.
- **F3c (descriptive 2x2).** Table of the four cells (fast/slow x noise 0/0.1) with Wilson intervals, discordant counts and unadjusted exact McNemar p per pair of cells, and per-cell counts. No verdict.
- **F4a, F4b, F4c (second model).** bnq n=200 one worker (F4a), n=200 four workers (F4b), n=100 one worker (F4c), p in {.84, .88, .92}: solved(ls_nb) - max(solved(cpsat_strong*), solved(cpsat_alt*)) >= +0.5 in >= 2 of 3 cells (point estimates). SUPPORTED = the LS advantage is not specific to one CP-SAT formulation. v3e: n=200 one worker cpsat_strong solved 0/20 in every cell. Earlier stages found the advantage over four-worker CP-SAT only at n=200 (n=100 not), so F4c is registered with one worker and F4b may fail; neither is changed after data.
- **F4d (descriptive).** Per cell, cpsat_alt vs cpsat_strong (one and four workers): counts, Wilson, discordant pairs, unadjusted McNemar p. No verdict.
- **F5a (interpreted ls_py on bnq).** bnq n in {100, 200} x p in {.84, .88, .92}: solved(ls_py) - solved(cpsat_strong) >= +0.5 in >= 5 of 6 cells. SUPPORTED = the bnq verdict does not depend on native code or on numba. **F5b:** |solved(ls_py) - solved(ls_nb)| <= 0.10 in >= 4 of 6 cells.
All verdicts are reported, none dropped. Primary label is not changed after data.
